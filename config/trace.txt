# ---- the first write --------------------------------------------------------
# Once a seeded image mounts with one damaged system block, CARDCheckExAsync
# repairs it, and that repair is the first byte this port has ever written to a
# card: one sector erase, then the block reprogrammed 128 bytes at a time. These
# sites follow that chain and name the three ways it can fail. Diagnostic only.

0x80248184  CardCheckExRepairDir    # the one-error arm: dir[bad] becomes current, the good twin is copied over it; r6 = the control block, r31 = CARDVerifyDir's error count
0x802481D0  CardCheckExRepairFat    # the same for the allocation table; r6 = the control block
0x80247704  CardUpdateDirErase      # bl __CARDEraseSector: r3 chan, r4 = sectorSize * ((currentDir - workArea) >> 13), the byte address of the sector about to be erased
0x802474A0  CardUpdateFatErase      # the same from __CARDUpdateFatBlock; r4 is the table block's byte address
0x80245678  CardEraseSector         # r3 chan, r4 the byte address, r5 the callback; command 0xF1, and the model erases one 0x2000 sector
0x80247044  CardWrite               # r3 chan, r4 card address, r5 length, r6 source, r7 callback; 0x80247078 cuts the length into len >> 7 page programs
0x802455A0  CardWritePage           # r3 = card->xferAddr just loaded from +176: the byte address of this 128-byte page program; fires 64 times per 8192-byte block
0x80244AEC  CardExiHandlerDone      # r3 chan, r4 the result __CARDExiHandler hands the transfer callback: 0 is a page programmed, anything else is the save failing
0x80244A84  CardExiStatusBad        # the card reported status & 0x18, a program or erase error -> -5 IOERROR; exi.c answers a constant 0x41, so firing means the model changed
0x80244A4C  CardExiFatalLock        # EXILock(chan, 0, 0) found channel 0 held, so the transfer ends -128 FATAL with no EXIUnlock; the RTC and SRAM share this channel
